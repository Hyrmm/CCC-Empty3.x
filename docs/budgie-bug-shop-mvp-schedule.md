# Budgie's Bug Shop 首版开发排期与任务拆分

## 0. 文档目的

本文档用于把 [budgie-bug-shop-design.md](D:\cocosProject\CCC-Empty3.x\docs\budgie-bug-shop-design.md) 中的首版设计，收敛为一份可以直接执行的开发计划。

目标不是一次性实现完整正式版，而是交付一个可验证核心体验的内部 Alpha：

- 抓虫是否足够爽
- 商店经营闭环是否成立
- 区域推进是否有价值感
- `Scarab` 是否形成长期目标
- 翻新是否真的值得点

---

## 1. 首版目标与范围

### 1.1 首版定位

首版建议定位为：

- 内部可玩 Alpha
- 用于验证核心双循环和一次翻新体验
- 允许资源占位，但不允许关键闭环缺失

### 1.2 首版范围冻结

基于设计文档第 17 节，首版范围建议冻结为：

- 2 个主场景
  - 商店场景
  - 抓虫场景
- 3 个区域
- 12 种虫
- 6 个基础升级
- 12 个核心永久技能
- 1 次完整翻新
- `Cosmic Scarab` 特殊目标
- 基础教程和新手引导
- 本地存档与读档

### 1.3 首版不做内容

为了控制首版工期，以下内容建议不进入首版：

- 周边商品深度扩展
- 分店系统
- 大规模被动收入体系
- 隐藏区域 / 天空区域 / 终局区域
- 复杂虫子特殊行为的大量铺开
- 完整图鉴、成就、排行榜
- 多端专项适配之外的渠道化工作

### 1.4 当前工程基线判断

结合当前工程结构，现状更接近“启动骨架已搭好，玩法层未开工”：

- 已有启动入口与 UI 配置骨架
- 已有基础框架初始化逻辑
- `assets/scripts/game` 目录尚未形成玩法实现
- 当前应按玩法系统从 0 到 1 估算工期

## 2. 首版验收标准

首版验收不以“功能数量”作为唯一标准，而以“闭环是否成立”作为主标准。

### 2.1 必须成立的 5 个体验点

1. 抓虫必须爽。
2. 回店必须能立刻赚钱和升级。
3. 新区域必须明显更值钱。
4. `Scarab` 必须形成长期驱动。
5. 翻新后必须明显变强。

### 2.2 Alpha 最低验收口径

满足以下条件即可视为首版完成：

- 玩家可完成完整流程：商店 -> 抓虫 -> 回店售卖 -> 升级 -> 解锁新区 -> 获取 `Scarab` -> 购买永久技能 -> 翻新
- 前 30 分钟存在明确成长节奏
- 第一次翻新收益清晰且有吸引力
- 商店与抓虫两个场景都具备基本可视反馈
- 核心流程不存在阻断性 bug

## 6. 系统任务拆分

### 6.1 客户端底层与流程

任务：

- 建立游戏主流程状态机
- 建立商店 / 抓虫场景切换机制
- 建立全局数据中心
- 建立配置读取与缓存机制
- 建立本地存档与版本迁移策略
- 建立调试面板与数值注入能力

产出：

- 游戏流程骨架
- 基础数据模型
- 可反复调试的开发环境

依赖：

- 无，属于全局先行任务

### 6.2 抓虫玩法系统

任务：

- 实现拖拽挥网输入
- 实现网范围、轨迹与命中判定
- 实现虫刷新器
- 实现虫行为模板
  - 漫游型
  - 高频转向型
  - 冲刺型
- 实现回合时间系统
- 实现清屏奖励
- 实现单局结算
- 实现局内反馈
  - 飘字
  - 粒子
  - 音效占位
  - 稀有虫高亮

产出：

- 单局抓虫体验可玩
- 抓虫收益可落到库存与区域经验

依赖：

- 配置结构
- 全局数据模型

### 6.3 商店经营系统

任务：

- 实现库存展示与消耗
- 实现顾客生成
- 实现顾客排队与柜台分配
- 实现订单结算
- 实现 Money 增加与展示
- 实现离店售卖简化逻辑
- 实现升级入口与购买反馈

产出：

- 抓虫结果可在商店中变现
- 玩家回店后可立即获得经营反馈

依赖：

- 库存系统
- 基础 UI 框架

### 6.4 区域与推进系统

任务：

- 实现 3 个区域配置
- 实现区域解锁费与入场费
- 实现区域经验与区域等级
- 实现区域售价倍率
- 实现区域内容切换
- 实现区域选择界面

产出：

- 区域之间形成明显收益差异
- 中循环推进成立

依赖：

- 抓虫玩法
- 商店货币流转

### 6.5 基础升级系统

任务：

- 实现 6 项基础升级数据结构
  - Marketing
  - Training
  - Expansion
  - Size
  - Time
  - Experience
- 实现升级购买逻辑
- 实现升级效果挂接
- 实现升级 UI 与反馈

产出：

- 每次回店都有可购买内容
- 玩家能感知到明确成长

依赖：

- Money 系统
- 区域 / 抓虫 / 商店相关效果挂点

### 6.6 `Scarab` 与永久技能系统

任务：

- 实现 `Cosmic Scarab` 产出逻辑
- 实现永久货币累计
- 实现永久技能数据结构
- 首版接入 12 个核心技能节点
- 实现技能树界面

- 中后期长期目标成立
- 翻新前存在积累动机

- 抓虫系统

### 6.7 翻新系统

## 9. 风险与控制策略

### 9.1 抓虫手感风险

风险：

- 命中不稳
- 抓到多只时不够爽
- 稀有目标不够显眼

控制策略：

- W2 结束前必须做一轮内部手感评审
- 命中判定允许适度宽松
- 清屏与稀有虫必须有强反馈

### 9.2 商店存在感风险

风险：

- 回店只是数字增长
- 玩家感受不到经营系统的参与

控制策略：

- 顾客、排队、交易节奏必须可视
- 升级后店铺吞吐变化必须能被感知
- 离店售卖结果需要被明确展示

### 9.3 翻新意愿不足风险

风险：

- 玩家觉得失去太多
- 看不懂翻新收益

控制策略：

- 翻新前必须展示重置项、保留项、收益项
- 第一次翻新收益必须明显
- 前几个保留类永久技能价格保持友好

### 9.4 数值膨胀风险

风险：

- 收益增长过快
- 前期内容失效

控制策略：

- 高价值区域通过门槛和入场费卡节奏
- 首版技能优先做规则改变，不堆纯倍率
- 离店收益设置软上限

## 10. 设计口径冲突修正建议

当前设计文档存在一个首版口径冲突：

- 第 17 节 MVP 范围建议为 3 个区域
- 第 16.14 节 30 分钟目标状态写到 4 到 5 区

这两者不应同时作为首版目标。

建议首版统一改为以下口径：

- 第 5 分钟：完成第一次升级
- 第 10 分钟：解锁第 2 区
- 第 20 分钟：解锁第 3 区
- 第 30 分钟：建立基础升级偏好，并对 `Scarab` / 翻新形成期待

这样可以保持：

- MVP 范围闭合
- 前 30 分钟目标可验收
- 不会因区域数量膨胀导致首版延期
